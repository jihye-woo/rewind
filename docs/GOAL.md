# 단어장의 목표 모습

Rewind 단어장이 최종적으로 어떤 모습이어야 하는지 적은 문서입니다. 정제 도구(MCP)는 이 문서를 기준으로 지금 단어장과 목표의 차이를 조금씩 줄입니다. 2026-11-21 지혜 님과 정한 내용이고, 바꿀 때는 날짜와 이유를 함께 적습니다.

## 1. 목적: 직접 말하기

단어장은 "알아보기"보다 **"말할 때 꺼내 쓰기"**를 위해 있습니다. 이 목적이 아래의 모든 기준을 정합니다.

- 예문은 실제로 말하거나 쓸 때 그대로 가져다 쓸 수 있는 문장입니다. 사전식 설명 문장은 고칩니다.
- **톤은 표현마다 다릅니다.** 일상 대화에서 쓰는 표현은 대화체로, 금융 용어는 시장·투자 이야기의 톤으로, 뉴스에 자주 나오는 표현은 뉴스 문장의 톤으로 맞춥니다. 뜻마다 톤(`register`: casual, business, finance, news, formal 등)을 적어 두고 예문을 거기에 맞춥니다. (2026-11-21 고침: 처음에는 "미드 대사처럼"이었음)
- 한국어로 하고 싶은 말을 보고 영어 표현을 고르는 방향(한→영)의 문제를 늘립니다.
- 뉘앙스 대비는 "말할 때 어느 쪽을 골라야 하는가"를 알려 줘야 합니다.

## 2. 구조: 표현 → 뜻

```
표현 (표제어, 원형)          예: apply
 ├─ 활용형                   applied, applies, applying     ← 표현에 붙는다. 뜻과 무관하다
 ├─ 발음                     /əˈplaɪ/
 └─ 뜻 (1개 이상)
     ├─ 뜻 1: 지원하다         예문, 뉘앙스 대비, 오답 보기, 자주 같이 쓰는 말
     └─ 뜻 2: 적용하다         예문, 뉘앙스 대비, 오답 보기, 자주 같이 쓰는 말
```

- **학습 단위는 "표현 × 뜻"입니다.** 카드와 진도는 뜻마다 따로 쌓입니다. apply(지원하다)를 잘 알아도 apply(적용하다)는 처음부터 배웁니다.
- **활용형은 표현에 붙습니다.** 뜻이 달라도 활용은 같기 때문입니다. applied 를 등록하면 apply 로 모이고, 빈칸 문제에서 활용형은 정답으로 인정합니다.
- 표현(`phrase`)도 같습니다. `set someone up with something` 의 활용형은 set ... up with 의 시제 변화이고, 뜻이 둘이면 뜻 두 개입니다.
- 예외(뜻에 따라 활용이 다른 경우 등)는 당분간 생각하지 않습니다. 보편적인 경우에 맞춥니다.

## 3. 좋은 뜻 하나의 기준

정제 도구는 이 표의 칸을 하나씩 채우고 고칩니다. 진단 도구는 이 표로 항목을 채점합니다.

| 칸 | 기준 |
| --- | --- |
| 한국어 뜻 | 한 줄. 같은 표현의 다른 뜻과 겹치지 않는다 |
| 톤 | `register` 하나. 예문과 활용 문장은 이 톤을 따른다 |
| 예문 | 10개 안팎. 서로 다른 상황. 표현 부분에 `[ ]`. 자연스러운 한국어 번역. 문장마다 보여 준 횟수를 센다 |
| 요즘 활용 문장 | 이 표현을 지금 쓸 만한 장면에 연결한 문장 2~3개. 톤에 맞게 고른다: 뉴스·금융 표현은 최신 뉴스·트렌드에서(제목, 출처, 날짜를 붙인다), 일상 표현은 요즘 일상의 새 장면에서. 모든 표현을 뉴스에 맞출 필요는 없다 |
| 원문 | 처음 만난 장면이 있으면 그대로 둔다. 정제할 때 지우거나 바꾸지 않는다 |
| 뉘앙스 대비 | 헷갈리는 유의어 2~3개. 각각 "말할 때 언제 이쪽을 쓰나" 한 줄, 그리고 그 유의어가 맞는 문장 1개 |
| 오답 보기 | 그럴듯하지만 틀린 뜻 3개, 비슷하게 생긴 빈칸 3개. 다른 뜻의 의미는 오답으로 쓰지 않는다 |
| 자주 같이 쓰는 말 | 2~3개 (예: apply for a job, apply to a school) |

## 4. 정제 원칙

- **바로 적용합니다.** 단어가 많아지면 하나씩 승인하기 어렵기 때문입니다. 대신 바뀐 내용은 모두 변경 기록에 남기고, MCP 의 정정 도구로 나중에 되돌리거나 고칠 수 있게 합니다.
- **지혜 님이 주기적으로 호출합니다.** 예약 작업은 두지 않습니다. 호출하면 기준에 못 미치는 항목부터 정해진 개수만큼 고칩니다.
- **요즘 활용 문장은 정제할 때마다 새로 고칩니다.** 표현의 톤에 따라 방법이 다릅니다. 뉴스·트렌드·금융 쪽 표현은 rewinds 를 실행하는 쪽(ChatGPT 등)이 그 시점의 뉴스와 트렌드를 검색해 출처·날짜와 함께 넣고, 일상 표현은 검색 없이 다른 일상 장면의 새 문장으로 바꿔도 됩니다. 서버는 검색하지 않고 받은 문장을 저장합니다. 오래된 활용 문장(90일이 지난 것)은 새 문장이 들어오면 바꿉니다. (2026-11-22 고침: 모든 표현을 뉴스·트렌드에 맞추지 않는다)
- **너무 많이 본 예문은 바꿉니다.** 한 문장을 100번 이상 보여 줬으면 정제할 때 같은 상황의 새 문장으로 교체합니다. 외워 버린 문장은 더 이상 연습이 되지 않기 때문입니다. 보여 준 횟수는 모든 사람의 학습을 합쳐 셉니다.
- **진도(`st`)는 건드리지 않습니다.** 내용(예문, 뜻 설명, 대비, 오답 보기)만 바꿉니다.
- **원문과 등록 시각은 지우지 않습니다.**
- 단어장은 친구들과 공유하므로 정제 결과는 모두에게 적용됩니다. 진도는 사람마다 그대로입니다.

## 5. 합치기와 나누기의 진도 규칙

구조를 고치다 보면 항목이 합쳐지거나(중복, 활용형) 나뉩니다(뜻 나누기). 이때만 진도를 옮기며, 사람마다 따로 적용합니다.

- **합칠 때:** 두 진도 중 **학습량이 많은 쪽을 통째로 고릅니다.** 학습량은 본 횟수(`seen`)로 비교하고, 같으면 반감기(`h`)가 긴 쪽을 고릅니다. 처음 학습한 시각(`intro`)은 둘 중 이른 쪽을 씁니다. 두 진도를 더하거나 평균 내지 않습니다. 더하면 실제보다 많이 안다고 보게 되기 때문입니다.
- **나눌 때:** 나뉜 뜻들이 원래 진도를 그대로 이어받습니다.
- 세션 기록은 고치지 않습니다. 없어진 항목 ID 는 새 ID 를 가리키는 별칭으로 남겨, 기록을 읽을 때 이어지게 합니다.

## 6. 지금과의 차이 (2026-11-21)

| 지금 | 목표 |
| --- | --- |
| 항목 하나에 뜻 하나 | 표현 하나에 뜻 여러 개 |
| 같은 텍스트를 다시 등록하면 뜻·설명은 처음 것만 남고, 다른 뜻의 예문이 섞여 들어온다 | 다른 뜻이면 새 뜻으로 추가한다 |
| applied 와 apply 가 따로 등록된다 | 활용형은 원형으로 모인다 |
| 뉘앙스 대비는 유의어 이름과 설명뿐 | 유의어마다 맞는 문장이 있다 |
| 예문은 최대 12개, 톤 구분 없음, 보여 준 횟수를 세지 않음 | 10개 안팎, 톤에 맞춤, 문장마다 횟수를 셈 |
| 요즘 활용 문장 없음 | 정제할 때마다 최신 뉴스·트렌드로 갱신 |
| 단어를 훑어보는 화면은 '항목' 목록과 상세뿐 | 학습과 별도로 단어 목록과 활용 문장을 훑어보는 메뉴 |
| 정제 도구 없음 | MCP 에 진단, 일괄 정제, 정정 도구 |

## 7. 만드는 순서

1. ~~**저장 구조를 "표현 → 뜻"으로 바꾸고 지금 항목을 옮깁니다.**~~ **끝남 (2026-11-22).** 항목 56개가 뜻 하나짜리 표현이 됐고, 뜻 ID 가 예전 항목 ID 와 같아 진도·세션은 그대로 이어진다. `server/catalog.mjs`, `scripts/migrate-senses.mjs`. 예전 ITEM 행은 되돌리기용으로 남겨 두었다(1~2주 뒤 지운다).
2~4. **진단, 일괄 정제, 정정: 끝남 (2026-11-22).** `server/rewinds.mjs`, MCP 도구 `rewinds_targets`(진단·대상) · `rewinds_apply`(한 번에 고치기, 합치기 포함) · `rewinds_history` · `rewinds_undo`. 고치기·되돌리기는 주인만. 뜻 나누기는 아직 없다(필요해지면 넣는다). 예문 노출 횟수는 2026-11-22 부터 센다(그 전 세션에는 어느 예문을 보여 줬는지 기록이 없다).
5. **목록 메뉴:** 학습(테스트) 말고, 단어 목록과 그 예문·요즘 활용 문장을 훑어보는 메뉴. 톤별로 거를 수 있게 합니다.
6. **새 문제 유형:** 뉘앙스 구분, 한→영 고르기 (1번의 목적에 맞는 순서로).

## 8. rewinds (정제 실행) 한 번에 일어나는 일

1. 진단: 기준에 못 미치는 뜻, 100번 넘게 본 예문, 90일 지난 활용 문장을 골라 우선순위 순으로 정해진 개수(예: 20개)를 꺼낸다.
2. 실행하는 쪽이 항목마다 톤을 확인하고, 모자란 칸을 채우고, 활용 문장을 새로 만든다. 뉴스·트렌드 톤의 표현만 검색하고, 일상 표현은 다른 일상 장면으로 바꾼다.
3. 한 번의 호출로 일괄 반영한다. 서버는 형식을 검사하고, 진도는 건드리지 않고, 바뀐 것을 변경 기록에 남긴다.
4. 결과 요약(몇 개를 고쳤고 무엇을 바꿨는지)을 돌려준다. 잘못 고친 것은 정정 도구로 되돌린다.
